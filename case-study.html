01

AI는 꽤 자주 썼지만, 일하는 방식은 그대로였습니다.

도움은 됐지만, 대부분 한 건씩 요청하고 결과를 가져오는 방식이었습니다.

01

AI는 이미 쓰고 있었습니다

문장을 다듬고 요약하고 초안을 잡는 데 썼고, 실제로 빨라졌습니다. 다만 쓰는 방식은 계속 같았습니다.

요청 예시
간단하게 요약해서 알려줘

한 건씩 맡기는 것만으로는 그 이상 나아가지 않았습니다.

도움은 됐지만 흐름은 그대로였습니다
  • 필요한 내용을 가져와서
  • AI에게 요청하고
  • 결과를 다시 업무에 붙입니다
02

AI에 맞는 일을 새로 찾지 않고, 하던 업무 하나에 그대로 넣어봤습니다.

세무달력은 이미 매달 하던 업무였고, 결과물과 원본 자료가 남아 있었습니다.

세무달력에서 배운 것은 AI가 잘하느냐보다 어떤 조건이면 맡겨도 되느냐였습니다. 기존 방식, 바뀌는 원본, 검수 기준이 있어야 실제 업무로 썼습니다.
03

그다음 질문은 AI로 무엇을 만들지보다, 하던 업무 어디에 붙일지였습니다.

세무달력을 넘어, 실제 기획 업무 여러 개로 범위를 넓혀 봤습니다.

03 · 적용 범위

지금은 이런 업무에 적용해 봤습니다

전부 원래 하던 일이고, 각자 필요한 자리를 나눠 적용해 본 결과입니다.

01
화면 스펙 작성
화면 항목을 추출해 스펙 규격에 맞춰 초안을 만듭니다. 정책과 예외 판단은 사람이 남깁니다.
02
기존 화면 찾기
링크·원문·날짜로 후보를 먼저 좁힙니다. 같은 화면인지 최종 판단은 사람이 합니다.
03
시안·기획서 대조
Zeplin 시안과 Figma 기획서 문구를 자동으로 맞추고, 구조·표기 차이로 생기는 오탐은 규칙으로 걸러냅니다. 반영 여부는 디자인팀이 정합니다.
04
정책·문서 정리
지라·위키·Figma에 흩어진 조건을 정해 둔 기준에 맞춰 모읍니다. 무엇을 정책으로 볼지는 사람이 정합니다.
05
세무달력
기존 방식에 새 원본을 연결해 매달 반복합니다.

여러 업무에 적용해보며 생긴 구분을, 맡길 일과 남길 일의 기준으로 정리했습니다.

AI로 무엇을 할지보다, 지금 하는 일을 어떻게 나눌지가 더 중요했습니다.

04 · 맡길 일과 남길 일

업무를 볼 때 네 군데로 나누어 보았습니다

이 네 군데를 나누면, AI에게 맡길 수 있는 자리와 사람이 봐야 하는 자리가 함께 보였습니다.

기존 방식
이 일을 어떤 모양과 규칙으로 하는지
바뀌는 자료
매번 새로 들어오는 정보가 어디 있는지
반복 실행
정해진 순서로 반복되는 단계가 무엇인지
사람 판단
기준·예외·최종 결정이 필요한 지점은 어디인지

반복은 맡기고, 판단은 남겼습니다

AI는 기획자의 일을 대신하지 않고, 사람이 판단하기 전의 반복 작업을 줄이는 쪽에 가까웠습니다.

AI에게 맡긴 일
  • 정해진 순서 실행
  • 자료 조회
  • 규칙에 따른 정리
  • 비교 가능한 기본 검수
사람이 남긴 일
  • 무엇을 할지 결정
  • 기준 결정
  • 예외 판단
  • 결과 판단 · 최종 확인

작게라도 수치로 남긴 변화

잘 되는 방식은 다음에도 쓰도록 남겼습니다

한 번 잡힌 기준과 자료 위치를 매번 다시 설명하지 않도록 폴더로 묶었습니다. 대화창에만 있으면 다음에 또 설명해야 하고, 팀원이 그대로 쓰기도 어렵습니다. 폴더로 남기면 다시 쓰고 팀에도 전달합니다.

tip/
├─ skills/month/SKILL.md # 업무 순서 · 표기 방식
├─ skills/qa/SKILL.md # 검수 절차
├─ commands/mg.md # 자주 쓰는 요청
├─ references/ # 스펙 · 원본 위치 · 구조, 문서 5개
└─ scripts/ # 검수 · 배포

다섯 가지 결과물은 한 포털에 모아 두었습니다

따로 실행 방법을 안내하지 않아도, 카드에서 설치하거나 바로 엽니다.

CLI 명령이 낯선 팀원에게는 포털의 설치 카드에서 토큰이 담긴 curl 한 줄을 대신 건넸습니다. 직접 띄워 둔 개인 서버를 거쳐 같은 결과로 끝나는, 실제로 돌아가던 경로였습니다.

전달 전 사내 주소, 계정 식별자, 캡처 속 이름과 사진은 제외했습니다.

실제 화면 · 설치 카드에 그대로 뜨는 curl 한 줄(주소·토큰 값은 가림)
Plugin 안은 스킬 · 커맨드 · 훅으로 나뉩니다
스킬
요청과 맞으면 Claude가 찾아 읽습니다. 예: "이 화면 스펙 작성해줘"
커맨드
사람이 이름을 직접 입력해 실행합니다. 예: /guide-qa
훅
정해진 상황마다 자동 실행됩니다. 예: 새 배포본 자동 갱신

셋 다 문서 한 장이고, 누가 부르는지만 다릅니다. 기획자도 열어서 고칠 수 있는 문서 형태입니다.
