오탐 제외 기준과 문서 구조를 더 깊게

인터뷰에서 짧게 다룬 대조 규칙과 폴더 구조를 기술적으로 더 풀어 쓴 자료입니다. 배경과 전체 맥락은 인터뷰에서 확인할 수 있습니다.

기술 상세 대조 규칙 · 문서 구조 · 배포 경로

오탐부터 줄이고 남은 항목만 사람이 본다

확정된 Zeplin 시안을 기준으로 두고 같은 화면의 Figma 기획서와 자동으로 대조한 뒤, 검수 리포트에서 반영·확인·표기 통일로 나눠 담당별로 보여준다.

화면 하나에 확인할 문구가 수백 건이었지만 실제로 고쳐야 할 항목은 그중 일부였다. 전부 다르다고 표시하면 아무도 보지 않으므로, 다른 항목을 더 찾기보다 잘못 걸리는 항목부터 줄이는 쪽을 택했다.

화면을 만드는 방식이 달라 같은 문구가 여러 조각으로 나뉘어 잡히면 다시 하나로 묶고, 표나 목업 안의 예시 데이터나 시안에만 있는 표시는 비교 대상에서 뺀다. 이렇게 정리한 오탐 제외 규칙이 8가지고, 남은 항목만 디자인 반영·기획 확인·표기 통일로 나눈다.

규칙으로 걸러내면 필요한 항목까지 빠질 수 있어서, 회차마다 왜 제외했는지 로그로 남겼다. 조용히 잘라내지 않기 위해서다. 무엇이 다른지 찾기 전에 무엇을 잘못 걸리는 것으로 뺄지부터 정해야 했고, 남은 항목은 담당을 정해 사람이 봤다.

폴더로 남겨 다시 쓰고 팀에 그대로 건넨다

한 번 잡힌 기준과 자료 위치를 매번 다시 설명하지 않도록 폴더로 묶었다.

대화창에만 있으면 다음에 또 설명해야 하고 팀원이 그대로 쓰기도 어렵다. 폴더로 남겨 두면 다시 쓰기도 하고 팀에도 그대로 전달할 수 있다. 세무달력 폴더 안에는 만드는 순서와 표기 방식을 적은 업무 순서 문서, 무엇을 어떻게 확인하는지 적은 검수 절차 문서, 매번 같은 말을 새로 쓰지 않도록 정리한 자주 쓰는 요청, 스펙·원본 위치·구조를 적어 둔 참고자료 5개, 검수·배포를 대신 해 주는 실행 도구를 넣어 뒀다.

tip/
├─ skills/month/SKILL.md # 업무 순서 · 표기 방식
├─ skills/qa/SKILL.md # 검수 절차
├─ commands/mg.md # 자주 쓰는 요청
├─ references/ # 스펙 · 원본 위치 · 구조, 문서 5개
└─ scripts/ # 검수 · 배포

이렇게 쓰면서 기준을 고친 기록은 모두 31건이고, 검수 항목 22개는 자동으로 확인하고 있다.

폴더 안 문서 셋은 언제 쓰이는지만 다르다. 스킬은 비슷한 요청과 맞으면 Claude가 스스로 찾아 읽는 문서다. "이 화면 스펙 작성해줘"라고 말하면 관련 문서를 알아서 참고하는 식이다. 커맨드는 정해 둔 이름을 사람이 직접 불러서 실행하는 문서고, 훅은 새 배포본이 올라오는 것처럼 정해진 상황이 생기면 자동으로 실행된다. 셋 다 기획자가 직접 열어서 고칠 수 있는 평범한 문서다.

팀에는 명령 두 줄로 전달했다

만든 것을 하나로 묶어서 팀원이 짧은 명령 두 번만 실행하면 설치되도록 했다.

도구 목록 등록부터 새 창 열기까지
01 목록 등록
/plugin marketplace add 주소
02 설치
/plugin install 이름
03 새 창 열기
새 창에서 적용

CLI 명령이 낯선 팀원에게는 포털의 설치 카드에서 토큰이 담긴 curl 한 줄을 대신 건넸다. 직접 띄워 둔 개인 서버를 거쳐 같은 결과로 끝나는, 실제로 돌아가던 경로였다.

전달 전 사내 주소, 계정 식별자, 캡처 속 이름과 사진은 제외했다.

실제 화면 · 설치 카드에 그대로 뜨는 curl 한 줄(주소·토큰 값은 가림)
스킬 · 커맨드 · 훅, 누가 부르는지가 다르다
스킬
요청과 맞으면 Claude가 찾아 읽는다. 예: "이 화면 스펙 작성해줘"
커맨드
사람이 이름을 직접 입력해 실행한다. 예: /guide-qa
훅
정해진 상황마다 자동 실행된다. 예: 새 배포본 자동 갱신

셋 다 문서 한 장이고, 누가 부르는지만 다르다. 기획자도 열어서 고칠 수 있는 문서 형태다.
